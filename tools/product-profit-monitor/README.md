# Product Profit 数据巡查与问题定位

本地开发版：定时检查 Product Profit、保存异常证据与历史，并根据业务问题查询和分解利润变化。延续 V2.0.1 的 Streamlit 界面和受控查询方式。开发、联调先在本机完成，测试通过后再部署公司服务器。

**[打开本机工具 →](http://127.0.0.1:8501)** · 需要先在自己的电脑启动下方程序；这不是 GitHub 托管的在线服务。

## 启动

需要 Python 3.10+（推荐 3.12）。Mac 可以双击本工具目录内的 `start.command`（仓库根目录同名快捷入口也可用），或在终端执行：

```bash
git clone https://github.com/pconlineyuxi/codex.git
cd codex/tools/product-profit-monitor
bash scripts/start.sh
```

第一次运行创建 `.venv` 并安装依赖；打开 <http://127.0.0.1:8501>。终端同时运行网页与巡查 worker，保持打开；按 Ctrl+C 停止。已有虚拟环境时不会自动升级依赖。需要更新时运行 `.venv/bin/python -m pip install -r requirements.txt`。

默认选择**演示数据**，无需数据库或 AI 密钥；合成样本与真实记录按模式隔离。页面先点击“运行一次演示巡查”，能看到成本缺失、运费偏高、有广告无销售三个例子。重复运行不会新增相同异常。业务问题页可以输入：

- 查昨天 SKU DEMO-COST 的产品成本缺失数据
- 查过去7天 SKU DEMO-SHIP 的运费占比异常
- 对 `DEMO-HEALTHY` 选择两个时间窗口，查看利润变化分解

解析草稿需要核对后执行。不支持的业务问题不能自动变成上游根因结论。

## 已实现

- 普通查询与 17 个可选规则；日期、平台、店铺、IR、SKU 等白名单筛选。
- 数据完整性与真实模式就绪门槛；空值不冒充零，截断不冒充检查成功。
- 按纽约时区每日调度、历史回看和未恢复窗口复查；独立 worker，不依赖网页访问。
- SQLite 运行记录、异常生命周期、去重、失败重试与通知发件队列。
- 新增、持续、恢复、复发跟踪；仅规则明确提供恶化阈值时判断恶化。
- 两个时间窗口的利润差异算术分解；成本缺失时拒绝给出完整利润归因。
- 飞书私聊适配器默认关闭，只允许已配置并确认的 Yuxi 接收人；演示和影子模式不发送。

## 真实数据联调

开发阶段可选择“真实数据测试（只读）”：店铺支持多选，留空查询全部；最多一年（366 天，含闰年），使用真实数据库查询；结果明确标记刷新完整性、币种和源日期时区未核实，不能用于正式巡查的异常生命周期或恢复判定。下方 Codex 模块可以定时生成只读核查报告，始终保留这些限制。

复制 `.env.example` 为 `.env` 并填写只读 PostgreSQL 连接。先阅读 [本地测试与接入说明](docs/local-testing.md)，核对时间、币种、业务规则和刷新完成契约。数据库连接配置不完整时会拒绝查询；不会自动退回演示数据。

“正式巡查数据”模式需要刷新任务在所有来源刷新提交后生成可信 `ready.json`，其覆盖范围必须包含查询窗口。不能用当前日期或最新订单时间伪装“刷新完成”。第一版只确认 Product Profit 结果视图，未接入上游源表；报告明确展示定位终点。

本地启动仅监听 `127.0.0.1`。公司服务器上线前需接入公司认证、HTTPS、数据备份和访问控制，不能直接将开发端口暴露到公网。

## Codex 每日只读核查

无需启动网页或 worker。在本目录运行：

```bash
.venv/bin/python -m bi_check_agent.codex_patrol --mode review --rules all
```

默认检查纽约时间前一个完整自然日（含周末）、全部平台和店铺、现有全部 17 条规则，沿用固定 `main_ir` 排除条件。指定历史日期可添加 `--date YYYY-MM-DD`。数据库继续使用本地 `.env` 的只读连接；查询失败不会替换成演示数据。

每次执行在 `.runtime/codex-patrol/review/<业务日期>/<执行编号>/` 生成 `report.md` 和 `report.json`，区分疑似数据问题与经营信号／符号待核查。Markdown 展示规则汇总及前 30 个分组，JSON 保留完整异常汇总与证据；两者均不输出订单行。`latest.json` 保存最新尝试，`last-successful.json` 保留最近一次查询成功的结果；查询成功不表示数据通过验证。字段缺失、无数据和执行失败分别标记，失败返回非零退出码。

销售额按 `sale_order.create_date` 当天应补齐；成本按 `order_outbound_history.scan_time` 实际出库后的夜间批次写入。`lifecycle_patrol.py` 分别读取创建日订单和扫描出库日商品，在次日 09:00 的日常巡查中复核，包括更早创建、本日才出库的商品。扫描时间已确认 UTC，创建时间按 UTC 解释并保留待确认假设；转为纽约日期时使用夏令时边界。只检查有效销售订单，保留原视图对 Walmart 取消状态的排除。订单+商品无法唯一匹配订单行、金额来源缺失或重复时单独报告，不按整单推定所有商品已出库。

创建/出库日复核按订单行 ID 读取直接订单来源 `bi.ba_profit_order_line_info`，输出 `lifecycle_review` 汇总，沿用固定 main_ir 排除。它与辅助观察的物化结果视图不是同一快照，不能将计数差解释成异常恢复。当前依据是业务预期时限，不是任务成功记录；只列超出预期仍命中的疑点，尚未自动回查更早未解决批次。原 17 条规则仍按订单/广告日期保留辅助观察，其中依赖数据到齐的原始计数变化不单独提醒。广告观察明确平台/店铺数和 SKU/日分组数；同日零净销售不代表广告无转化。

Codex 使用 [product-profit-patrol 技能](codex-skills/product-profit-patrol/SKILL.md) 调用此模块。每日任务设为纽约时间 09:00，每次保存报告，有可反馈信号变化、检查失败或需要处理的事项时反馈。此方式依赖本机文件、数据库网络及 Codex 调度运行条件；不执行原 worker 的正式异常恢复或飞书发送。规则命中可能相互重叠，不可相加当作异常订单数；刷新完整性、币种及源日期时区尚未核实，需由 BA 进一步核对。


### 利润变化分析与数据问答

在侧边栏选择“利润变化分析”，同时核对本期、对比期和业务范围。默认上一等长周期；支持自定义日期，结束日期包含当天。可加载两个时期内的平台/店铺选项，并指定产品及其他筛选。整体差异按销售额、促销、产品与改装成本、佣金、广告、运费拆分；两个时期的汇总表可查看及下载。

读取进度按时期和天数展示。成功结果保留在当前浏览器会话，修改范围或分析失败时保留旧结果并暂停问答；重新分析成功后开启新的对话上下文。页面刷新重建会话或服务重启后需重新分析。

下方“就这份数据继续提问”使用 `.env` 中的 `OPENAI_MODEL` / `OPENAI_API_KEY`，仅在提问时调用模型。分析完成后，服务端会话保留两个时期经业务筛选、尚未汇总的完整源记录。模型必须通过受控分析工具对源记录进一步筛选、统计、分组比较或查看相关样本；不再使用页面汇总表或前 160 条汇总记录作为分析数据集。统计先处理全部匹配源行，再限制返回分组数；两期比较先连接完整分组，再按变化排序。缺失值及一侧无记录不会自动当作零。

模型可接收按需选取的源记录样本（每次最多 30 条），用于解释细节；样本数量和覆盖范围会标注，不能以抽样代替总体统计。页面和下载仍只展示汇总结果，问答凭据只展示样本检查的条件与数量，不提供订单行列表。模型没有 SQL、任意 Python、文件、联网、数据库写入或通知工具，不能自行扩大查库范围。

问答支持最近六轮对话；每次最多五轮源数据工具交互，然后回答。回答可展开核对工具参数、参与计算的源记录数及证据编号。旧版分析未保留源记录，需要重新执行“开始利润分析”后才能使用新问答。

缺失成本、无数据或币种/刷新凭据不一致时拒绝给出完整利润分解，不将缺失视为零；真实测试模式的币种、源日期时区与刷新完整性仍待验证。差异贡献只是算术解释，不能证明业务或数据问题的根因。


所有查询、巡查、利润分析和平台/店铺选项加载均固定应用 `main_ir NOT IN ('SHIPPING FEE', 'SHIPMENT DISCOUNT', 'GIFT WRAPPER FEE', 'PROMOTION DISCOUNT')`，页面业务筛选不能覆盖此条件。SQL NOT IN 同时排除 NULL main_ir。AI 使用同一查询返回的筛选后源记录。更新此口径后，旧会话结果和源数据上下文失效，需要重新查询或巡查。

## 内部结构与版本维护

规则元数据统一维护在 `config/diagnostic_rules.yaml`；查询结果与分析快照由 `bi_check_agent/contracts.py` 校验。代码版本用于审计和缓存，业务版本用于巡查身份。修改业务计算公式或固定 SQL 口径时必须递增 `POLICY_REVISION`，更新代码与规则目录后重启页面和巡查进程。兼容范围、历史记录处理及验收说明见 [内部结构整理](docs/superpowers/specs/2026-10-21-internal-contracts-design.md)。
