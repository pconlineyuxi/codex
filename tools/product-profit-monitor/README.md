# Product Profit 数据巡查与问题定位

本地开发版：定时检查 Product Profit、保存异常证据与历史，并根据业务问题查询和分解利润变化。延续 V2.0.1 的 Streamlit 界面和受控查询方式。开发、联调先在本机完成，测试通过后再部署公司服务器。

**[打开本机工具 →](http://127.0.0.1:8501)** · 需要先在自己的电脑启动下方程序；这不是 GitHub 托管的在线服务。

## 启动

需要 Python 3.10+（推荐 3.12）。Mac 可以双击本工具目录内的 `start.command`（仓库根目录同名快捷入口也可用），或在终端执行：

```bash
git clone https://github.com/pconlineyuxi/codex.git
cd codex/tools/product-profit-monitor
bash scripts/start.sh
```

第一次运行创建 `.venv` 并安装依赖；打开 <http://127.0.0.1:8501>。终端同时运行网页与巡查 worker，保持打开；按 Ctrl+C 停止。已有虚拟环境时不会自动升级依赖。需要更新时运行 `.venv/bin/python -m pip install -r requirements.txt`。

默认选择**演示数据**，无需数据库或 AI 密钥；合成样本与真实记录按模式隔离。页面先点击“运行一次演示巡查”，能看到成本缺失、运费偏高、有广告无销售三个例子。重复运行不会新增相同异常。业务问题页可以输入：

- 查昨天 SKU DEMO-COST 的产品成本缺失数据
- 查过去7天 SKU DEMO-SHIP 的运费占比异常
- 对 `DEMO-HEALTHY` 选择两个时间窗口，查看利润变化分解

解析草稿需要核对后执行。不支持的业务问题不能自动变成上游根因结论。

## 已实现

- 普通查询与 17 个可选规则；日期、平台、店铺、IR、SKU 等白名单筛选。
- 数据完整性与真实模式就绪门槛；空值不冒充零，截断不冒充检查成功。
- 按纽约时区每日调度、历史回看和未恢复窗口复查；独立 worker，不依赖网页访问。
- SQLite 运行记录、异常生命周期、去重、失败重试与通知发件队列。
- 新增、持续、恢复、复发跟踪；仅规则明确提供恶化阈值时判断恶化。
- 两个时间窗口的利润差异算术分解；成本缺失时拒绝给出完整利润归因。
- 飞书私聊适配器默认关闭，只允许已配置并确认的 Yuxi 接收人；演示和影子模式不发送。

## 真实数据联调

开发阶段可选择“真实数据测试（只读）”：店铺支持多选，留空查询全部；最多一年（366 天，含闰年），使用真实数据库查询；结果明确标记刷新完整性、币种和源日期时区未核实，不能用于正式巡查的异常生命周期或恢复判定。下方 Codex 模块可以定时生成只读核查报告，始终保留这些限制。

复制 `.env.example` 为 `.env` 并填写只读 PostgreSQL 连接。先阅读 [本地测试与接入说明](docs/local-testing.md)，核对时间、币种、业务规则和刷新完成契约。数据库连接配置不完整时会拒绝查询；不会自动退回演示数据。

“正式巡查数据”模式需要刷新任务在所有来源刷新提交后生成可信 `ready.json`，其覆盖范围必须包含查询窗口。不能用当前日期或最新订单时间伪装“刷新完成”。成本与销售候选已增加受控来源核查；补齐任务完成记录尚未接入，报告明确展示已核实事实及定位终点。

本地启动仅监听 `127.0.0.1`。公司服务器上线前需接入公司认证、HTTPS、数据备份和访问控制，不能直接将开发端口暴露到公网。

## 巡检工具、每日 Skill 与定时任务

完整规则、阈值、业务例外、历史状态和提醒节奏见 [统一巡检规则](docs/patrol-rules.md)。唯一配置是 `config/diagnostic_rules.yaml`；网页／手动工具和每日核查共用数值规则与 `patrol_policy.py` 适用性判断。网页按用户查询日期读取物化视图，每日核查额外按创建日／扫描出库日读取直接来源，不能把不同范围的数量差当成恢复。

**巡检工具**负责查询、判断、跟踪和归档；**[每日 Skill](codex-skills/product-profit-patrol/SKILL.md)** 负责调用工具并解读通知；**Codex 定时任务**每天纽约时间 09:00 触发 Skill。Skill 与定时提示不再另存一份规则阈值，也不自行根据订单年龄推断取消。

无需启动网页或 worker，从本目录运行：

```bash
.venv/bin/python -m bi_check_agent.codex_patrol --list-rules
.venv/bin/python -m bi_check_agent.codex_patrol --mode review --rules all
```

第一条仅显示规则，不连接数据库。第二条使用真实只读连接，默认检查纽约前一个完整自然日、全部平台及店铺，并复查历史已记录疑点。可指定 `--date YYYY-MM-DD`；失败不替换为演示数据。每次在 `.runtime/codex-patrol/review/<业务日期>/<运行编号>/` 归档 Markdown 和 JSON。

提醒可列出 `sale_order.name` 业务订单号，保留平台／店铺／SKU 汇总，不导出订单行明细、客户信息或数据库主键。旧报告只能按原日期和分组回查，当前订单号标为“本次分组匹配”，不能宣称恢复了旧订单身份。成本规则可能重叠，不把多个规则计数加总当订单数。

`tracking-state.json` 保留稳定身份、状态和通知时间，权限 0600，不提交 Git、不展示、不删除重置。业务例外为 `exempt`，长期未履约待核对为 `deferred`；都不声称金额已修复，前者不持续提醒，后者持续复查但仅状态变化提醒。来源消失、重复、缺字段或失败仍是 `unknown`。`notification.should_notify` 为通知依据；主查询失败时也尝试历史复查。`last_notified_at` 是提醒生成归档时间，不是外部消息送达凭据。

规则文档由 `.venv/bin/python -m bi_check_agent.rulebook` 生成。修改配置或代码后运行测试并重新生成文档；若网页或原 worker 在运行，需重启加载新版本。每日 Skill 及其真实连接依赖本机与网络，不执行网页 worker 的正式异常恢复，不发送飞书，不修改业务数据；刷新完整性、币种、创建时间解释和补跑任务成功记录限制仍需保留。


## 内部结构与版本维护

规则元数据统一维护在 `config/diagnostic_rules.yaml`；查询结果与分析快照由 `bi_check_agent/contracts.py` 校验。代码版本用于审计和缓存，业务版本用于巡查身份。修改业务计算公式或固定 SQL 口径时必须递增 `POLICY_REVISION`，更新代码与规则目录后重启页面和巡查进程。兼容范围、历史记录处理及验收说明见 [内部结构整理](docs/superpowers/specs/2026-10-21-internal-contracts-design.md)。

## 统一适用条件与原因核查（2026-10-27）

网页查询、手动巡查、正式计划和 Codex 日检均在 `service.query → diagnostics.build` 生成同一份判定。原 17 条规则仍保留候选明细；页面及 Codex 报告另展示等待数据、无法判断、经营观察、疑似错误和已验证数据差异。状态汇总按业务对象去重，跨规则命中数不能相加。Codex 额外按创建/出库事件覆盖的批次单列说明范围。

成本候选只读核对原始订单行成本、出库商品匹配、预期补齐时点、成本来源及物化结果；同一次来源核查同时读取来源与结果金额。多条订单行无法唯一对应时不强行关联。动态订单来源视图读取使用 UTC 会话，保证其显式纽约日期转换与物化结果匹配；仍要求完整日期与业务键准确对应，不通过放宽匹配掩盖差异。

任务运行记录尚未接入。已经确认的原始字段缺失或上下游金额差异，与尚待验证的任务/计算原因分别展示，不能据此声称某个补齐任务失败。读取失败、超限、数据变化时标记无法判断。正式巡查中等待或无法核实的候选不新建可行动异常；原对象消失或仍未核实也不自动标为恢复。

“核查证据与 BA 核实记录”可以保存真实错误、正常业务、等待数据或证据不足的结论及依据，记录在本地 SQLite，按数据模式隔离，规则调整仍需复核。问答可调用受控核查证据工具；增加了无依据数字和无条件原因断言的校验及一次自动修正机会。这些检查降低错误解释风险，不等于已经证明所有自然语言结论正确。

业务策略升级为第 2 版；历史数据保留，新判断不会沿用旧策略的异常身份。销售与退款抵消、订单成本与广告占位值一起算平均均不是用户确认的业务情形，不作为本轮规则改造或验收依据。现有利润计算仍分别加总订单成本和广告费用。
