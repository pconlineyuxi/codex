# 统一巡查判定与原因证据

2026-10-27。用户批准执行优化，并明确网页与 Codex 保持一致；销售与退款抵消不属于已确认业务情形，不据此新增规则。

所有入口继续复用 service.query，在同一处生成结构化判定：规则候选、适用条件、等待/未知/经营观察/疑似错误/已验证差异、原因状态、已验证事实及缺少证据。17 条原始规则保持为可核对的候选检测器；正式异常历史只接收可行动结果，未知和等待不触发恢复。

成本核查按订单、SKU、IR、平台、店铺、日期进行精确匹配；多匹配不强行归属。受控 SQL 在同一语句中读取订单行原始成本、直接利润来源、出库情况和物化结果。区分未出库、尚未到补齐时点、来源缺失、关联不唯一、原始字段为空和结果/来源不一致。验证了数据差异不等于验证了批次失败；任务日志未接入时明确保留原因待验证。来源不一致、查询失败、超限时不输出已确认原因。

真实联调发现动态来源视图的日期转换受读取会话时区影响。原因核查限定 UTC 会话，使用视图内显式纽约转换，并继续验证物化记录的精确时间键，禁止放宽日期匹配。原利润查询仍以原纽约日范围执行。

现有利润计算分别汇总订单成本与广告费。用户明确不存在把订单成本与广告占位零值一起算平均的业务情形，该假设从优化依据及验收移除。回答中的数字和因果断言增加程序校验；原因结论通过专门工具读取已验证事实，不能由模型自行提升状态。

网页展示同一份判定汇总并允许 BA 保存核实标签与依据；Codex 报告使用同一诊断结果。已有按创建/出库事件的额外覆盖仍单独说明范围。历史对象消失/未知时保留未解决状态，不认定恢复。业务策略升级隔离旧结论，审计记录保留。

验收覆盖：入口一致、未出库不误报、过时点仍缺成本、来源重复/无法匹配、原始 NULL 与零、视图不一致、源查询失败/截断、无依据数字/原因、无对象不得恢复、反馈持久化与作用域；全套旧功能测试回归。真实效果需要经 BA 核实案例及任务日志，不能用合成测试声称误报率下降。
