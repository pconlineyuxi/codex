# Product Profit 内部结构整理

范围由本次架构评审后的用户确认确定：统一规则、统一查询与分析结果结构、分离代码版本和巡查业务身份。保留现有页面、17 条规则、阈值、SQL 口径、只读访问及通知发送条件。

## 设计与实现

选择在现有扁平包内增加两个边界模块，不采用全面重写或仅调整文件夹的方案。

`config/diagnostic_rules.yaml` 是唯一规则元数据目录，包含中英文名称、别名、计算粒度、必需字段及巡查分组标签。`rule_catalog.py` 提供不可变定义；请求验证、解析器、检查服务、报告和生命周期复核读取同一目录。`core.py` 保留明确的计算公式，阈值读取现有 YAML；新增规则时需同时实现公式并增加正反样本。`missing_product_cost` 的必需字段为空是有意设计：成本缺失本身就是该规则的检查对象，不能先将其判为无法检查。

`contracts.py` 定义 Pydantic `QueryEvidence`、`QueryResult` 和 `AnalysisSnapshot`，在生产者返回前校验请求日期、模式、完整性、数据行数和各期证据。对外仍返回普通字典，保持现有页面、脚本及 JSON 记录兼容；DataFrame 保持原对象，不复制、不转换成订单明细列表。巡查和利润比较使用同一快照字段集合，巡查没有对比期。`public_dict()` 排除源 DataFrame，现有公开证据函数继续排除 `_source_frames`。三个问答入口共用 `analysis_status()` 判断数据是否存在、范围是否变化、最近查询是否失败。

`rule_source_version()` 继续作为完整代码与配置指纹，保留原函数名及证据字段，负责缓存失效、执行期间变化检测和运行审计。`diagnostic_policy_version()` 表示业务语义：由显式 `POLICY_REVISION`、规则粒度与必需字段、分组标签、业务阈值、guard 条件及筛选映射计算。注释、标签、别名、连接实现变化不改变异常身份；Python 公式、固定 SQL 条件、NULL 处理、日期/币种解释及 finding key 计算变化必须显式提高 `POLICY_REVISION`。这些规则是维护约定，不能把代码格式变化自动当作业务变化。

巡查范围由计划业务配置和业务版本决定。普通代码升级后，同一天也会重新检查，沿用原 run/incident ID、恶化基线和故障序号。不同业务口径或计划版本互相隔离；新口径不能将旧口径的异常标记恢复。

## 兼容与部署边界

增加 `scope_aliases` 表，将新业务范围映射到已验证等价的旧存储范围；不改写既有 run/incident ID、history 或 outbox UUID。已核实的兼容源版本是本次重构前的 `8e9a76...` 和 `e903cd...`；后者与前者的差异只有汇总展示保留 day 的修复，不影响巡查 finding。多个等价历史版本同时存在时采用最新版本的范围，旧代际记录保留历史；不自动合并冲突。更早仅对 YAML 计算哈希的版本无法证明 SQL/公式一致，保留隔离，不能自动认定等价。

映射在首次访问相应范围时幂等创建，并沿用现有 SQLite 事务与租约。执行中的有效旧租约仍阻止重复领取；失败窗口继续重试。业务版本真正改变时不建立兼容映射。迁移本身不产生通知；待发送消息保持原 UUID，是否发送仍遵守当前计划和现有发送条件。

更新代码和规则目录后需要重启页面及巡查进程。目录定义在进程启动时加载；如果运行期间目录发生改变，查询会要求重启，避免旧解析器和新规则元数据混用。不要使用热更新来跨越部署版本。

## 验证与验收

基线为修改前的 121 项测试。新增验证覆盖所有 17 条规则的命中/不命中样本、缺失成本与未知输入的区别、证据与源记录一致性、源 DataFrame 不复制、两类快照字段一致且公开导出不含源记录、聊天状态、代码更新后的异常连续性、业务变化隔离、两种旧版本兼容、租约/故障/通知标识保留及执行期间变更拒绝。

`tests/fixtures/pre_refactor_demo.json` 在修改代码前保存，全部为合成演示数据。回归检查将新实现的 SQL、源数据、汇总、异常命中、缺失输入和利润分解与该基线逐项比较。现有 Streamlit AppTest、受限源数据工具和模型模拟测试继续运行。测试不调用生产数据库、不发送通知、不使用真实付费模型。

本地既有状态库的兼容性验证在临时副本中进行；原记录只读，不在本次重构中直接迁移或执行真实巡查。

实施验收结果（2026-10-21）：`.venv/bin/python -m pytest -q` 最终为 **154 passed**，`git diff --check` 通过。临时状态库副本中的 1 个当前计划建立了 1 个兼容映射，保留 18 个未恢复复查窗口；映射前后 runs、incidents、history、outbox 内容逐项相同。
