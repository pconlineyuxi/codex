# 巡检来源证据与出库关联优化

用户已在 2026-11-04 批准根据专项核查发现的问题优化工具，并要求新产品零成本时先查 PO。采用已讨论的实证关联与成本追溯方案，不把没有 PO 自动等同合理零成本；不再采用 SKU 级永久豁免来处理本次赠品。

## 交付与边界

1. 抽出只读出库关联模块：单行继续使用既有唯一匹配；多行的 SN 商品用订单、商品、SN 与完成的销售出库库存移动对应；无 SN 商品仅在所有候选销售记录完整交付、当日完成出库数量与扫描合计完全一致时纳入成本复核。部分出库、退货、重复来源和数量不一致保持缺口。
2. 抽出零成本来源模块：仅追查实际基础成本为零的记录，检查有效 PO、当前采购价、已完成入库及入库业务日志。新产品自动获得来源解释，无 PO 本身不关闭疑点。
3. 赠品判定以配置中明确允许的原始入库说明、零价无采购关联入库及完整来源覆盖为依据；排除混合来源、无来源、负数、超量消耗、来源读取失败等情况。任何付费或来源不明的入库不能被赠品识别覆盖。
4. 每日批次及历史复查共用上述模块；公共报告包括实际商品、相关父 SKU、业务订单号、关联依据及成本来源说明，不输出内部主键。业务例外与关联可核对的状态变化只提醒一次；保留既定高优先级每天、普通每三天节奏。
5. 网页共享同一业务适用性与成本来源判断；物化结果本身不唯一时仍不能强行归属。Skill 只解释工具输出，不另设赠品规则。

## 实施与验收

- 先实现证据查询与纯函数判断，保留批量查询、读取上限及失败可见性。
- 接入生命周期、历史跟踪、共享诊断；更新策略版本、生成规则文档及 Skill。
- 用同单多件、不同 SN 成本、无 SN 附件、部分出库、退货、重复记录、混合采购、无 PO 非赠品、缺字段／查询失败覆盖测试。
- 运行全部已有测试，使用本次已归档的 8 张关联订单和 2 张零成本订单做离线回放；随后使用真实只读连接验证指定对象及一次完整巡检。
- 保留原跟踪文件，不删除／重置，不修改业务数据或正式异常状态；验证归档与去重结果后交付。

## 取舍

采用可解释的确定性证据，避免根据自由文本关键词或 LLM 猜测批准例外。对无 SN 且存在混合入库来源的商品宁可保留核对，不推断逐件成本来源。扩展范围止于本次关联和零成本追溯，不重做整个诊断服务。
